# 브라우저 재방문 통계

2026-11-11 구현. `/owner/usage`의 최근 방문 표에서 브라우저별 누적 방문 횟수·첫 방문·최근 방문을 확인한다.

## 집계 기준

- 첫 화면과 모델 페이지에서 `crypto.getRandomValues`로 128비트 무작위 식별값을 만들고 `localStorage.cb_browser`에 저장한다. 생성 후 365일이 지나면 새 값으로 바꾼다.
- 로그인 계정·이메일·IP에서 식별값을 만들지 않는다. IP 원문을 저장하지 않는다.
- 기존 방문 번호 `sessionStorage.cb_visit.sid`를 유지한다. 같은 탭의 페이지 이동·여러 번의 전송·재전송은 한 번으로 센다. 새 탭, 외부 사이트에서 다시 들어오기, 페이지 이동 시 이전 기록과 30분 이상 간격은 새 방문이다. 실제 사람 수를 뜻하지 않는다.
- 새 기록은 브라우저와 방문 번호로 묶는다. 예전 기록은 기존 IP 일별 해시 집계를 유지하고 `재방문 식별 없음`으로 표시한다. 과거 기록을 새 식별값에 소급 연결하지 않는다.
- 관리자 화면의 1일·7일·30일·특정 날짜 필터와 별개로 해당 브라우저의 보유 기록 전체(한국 날짜 기준 최근 365일)를 집계한다. 첫 방문·최근 방문도 이 범위 기준이다.
- 브라우저 저장소 삭제·식별값 만료·다른 브라우저·다른 기기는 별도 방문자다. 저장소 접근이 막히면 기존 방문 기록은 남기되 브라우저별 재방문은 식별하지 않는다.
- 첫 화면과 모델 페이지의 식별값 생성 부분은 같은 규칙을 유지한다. 회귀 검사는 두 실제 수집 코드를 각각 실행한다. `beta.html`과 `app/templates/beta.html`도 함께 갱신한다.

## 저장과 장애 처리

`api/usage.py`가 `vid`를 정확히 32자리 소문자 16진수로 검증한다. 기존 `usage_events.entry` JSON에 저장하므로 데이터 이동은 필요 없다. `pgstore.ensure_schema()`가 `vid` 조회용 인덱스를 만든다.

`pgstore.browser_history()`는 `COUNT(DISTINCT sid)`로 중복 전송을 제외한다. 별도 누적 표를 두지 않아 원본 기록을 지우면 집계에서도 빠진다. 집계 쿼리에는 화면 조회의 5,000건 상한을 적용하지 않는다. Neon 연결이 없거나 누적 조회가 실패하면 `누적 집계 확인 불가`로 표시하며 첫 방문이라고 추정하지 않는다.

`/?notrack=1`은 해당 브라우저의 기록을 끄고 브라우저 식별값을 지운다. 이미 열린 다른 탭도 다음 전송 때 끄기 상태를 확인한다. `/?notrack=0`으로 다시 켤 수 있다. 관리자 제외 쿠키와 봇 제외 동작을 유지한다. 개인정보 안내의 한국어·영어·일본어에 저장 방식·기간·끄기 링크를 반영했다.

```sh
python3 -m pytest tests/test_browser_visits.py tests/test_usage_log.py tests/test_owner_usage.py tests/test_pgstore.py tests/test_pgstore_blob.py tests/test_legal_pages.py -q

```

- Python 33개, JavaScript 9개 통과.
- 임시 PGlite(PostgreSQL)에서 실제 스키마·인덱스·집계 SQL 실행: 중복 전송, 서로 다른 브라우저, 365일 범위, 삭제 반영 확인.
- 로컬 Chromium에서 실제 수집 코드 → Python 수집 API → 임시 PostgreSQL → 관리자 화면 연결 확인. 오늘 필터로도 40일 전 이력을 포함한 누적 3회 표시, 관리자 미인증 401, 관리자 기록 제외 확인. 운영 DB에는 테스트 기록을 쓰지 않음.
- 데스크톱·휴대폰 표 확인. 좁은 화면에서는 표 안에서 좌우 스크롤.
